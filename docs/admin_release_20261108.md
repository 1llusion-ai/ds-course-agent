## 后续重建与回退

主线归档后，服务器使用 `deploy/compose.yaml` 和本机
`var/deployment/compose.runtime.json`。后者仅保存既有课程数据挂载、模型环境文件和索引绑定，
不覆盖镜像名称；`var/deployment/.env` 保存当前镜像的 Git SHA 标签。两者均不进入 Git。

```bash
cd /opt/ds-course-agent
./deploy/update.sh          # 只预览，不 fetch、构建或切换
./deploy/update.sh --apply  # 显式执行：快进 main、构建、健康检查、保存版本
```

普通更新按完整 Git SHA 标记镜像，并记录 OCI revision；失败时使用切换前实际运行的镜像回退，
继续沿用资源绑定。镜像回退不恢复数据库，涉及不兼容数据库迁移时仍需专门的迁移与恢复方案。

这次归档复用已验收镜像的依赖层，逐文件验证后台源码与前端构建产物后补充 Git revision 标签，
没有重新迁移账号或学习数据。后续常规更新由主线 Dockerfile 构建。
